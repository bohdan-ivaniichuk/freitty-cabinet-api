# 0006 — UUID v7 keys, created by the domain

- Status: accepted
- Date: 2026-11-17

## Context

The `Order` aggregate creates children and addresses them by id — record an operation on this
shipment, resolve that alert — and those ids are what the write API will carry. Its rules are
unit-tested without a database ([ADR 0003](0003-order-is-one-aggregate.md)). With keys generated by
the database or by EF Core, a new entity has no identity until a context or an insert gives it one,
so those methods could not be called on an order that was just built.

## Decision

Every primary key is a `uuid` holding a version 7 UUID. The entity assigns it in its constructor
with `Guid.CreateVersion7()`; EF Core is told the key is never generated (`ValueGeneratedNever`).

Outside the API an order is still identified by its number (`FR001383`), not by its id.

## Alternatives

- **`int` identity columns** — four bytes, readable in `psql`, the default everyone knows. Rejected:
  identity exists only after an insert, which makes the aggregate untestable without a database;
  sequential ids are also enumerable if they ever leave the API.
- **Integer keys from a HiLo sequence** — small and assigned before the insert. Rejected: they are
  assigned when the entity is added to a context, which a unit test of the domain does not have.
- **UUID v4** — the same properties in code. Rejected: random values scatter inserts across the
  B-tree; version 7 starts with a timestamp, so new keys land at the end of the index like a
  sequence.
- **UUID v7 generated by EF Core or by PostgreSQL (`uuidv7()`)** — no call in the domain. Rejected:
  the id would again not exist until the entity is tracked or inserted.

## Consequences

- An entity has its identity from the moment it exists; unit tests address children by id.
- Version 7 ids are ordered by millisecond, not strictly by creation: they keep the index compact
  and are a stable tiebreak, but "insertion order" is a question for an instant column.
- Keys can be created by any system without coordination — relevant once the hub system and the
  cabinet exchange orders.
- Keys and foreign keys take sixteen bytes instead of four. Irrelevant at this size.
- `Guid.CreateVersion7()` reads the system clock. It is the only place the domain does, and the
  timestamp it embeds is not business time: it orders the index and nothing reads it.
- A version 7 id reveals when the row was created. Accepted; nothing here is secret about that.
- `ValueGeneratedNever` is load-bearing. Without it EF Core takes a new child with a key for an
  existing row and issues an `UPDATE`; an integration test covers exactly that case.
